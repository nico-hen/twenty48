Structure

Five modules, ordered by distance from pure logic

One flat package. Position on the ladder is the dependency direction — everything points down, toward the pure core. Colour is purity: gold is the tested heart, orange is the outside world, brown is the one module that may read the environment.

further from pure logic ↑
__main__.py Composition root. Builds the real RNG, the starting Board, the termios key-source, stdout, and — only if a credential exists — the Claude Advisor. 43 stmts · the only module that reads os.environ · imports anthropic lazily
↓ injects every effect ↓
loop.py The turn cycle: render, read one key, move-then-spawn or reject, and on H ask the Advisor. Every side effect arrives as an argument. 37 stmts · nothing here catches: the Advisor cannot throw
↓ drives ↓
ui.py Rendering and key parsing, both pure. The raw-mode reader is the one impure adapter, kept to 13 lines. 54 stmts
advisor.py The Advisor protocol and its one Claude-backed implementation. The HTTP client is injected, described by four small structural protocols. 65 stmts
↓ both depend only on ↓
board.py The Move enum and the frozen Board value object. Slide, merge, legality, win, loss, spawn. No I/O, no randomness of its own — the RNG is injected. 80 stmts · pure · every transformation returns a new Board
  • Nothing below the advisor line knows Claude exists. Not even advisor.py imports the SDK — it declares the slice of the client it calls and takes it as a constructor argument.
  • Nothing but __main__.py touches the environment. One file to audit for "does this leak a credential?", and it is 43 statements long.
ADR-0002

One flat package, layered by purity

Chose a flat twenty48/ package of five small modules ordered by distance from pure logic, over a src/ layout or an advisor/ sub-package.

Rejected

  • ✕ src/ layout — marginally more correct for packaging, but ceremony out of proportion to a small terminal game.
  • ✕ advisor/ as a package — deferred until a second implementation actually exists. No speculative directory.

Consequences

  • →The package is twenty48, not 2048 — a module name cannot start with a digit.
  • →Credential handling is confined to one file, so there is exactly one place to audit.
  • →The test suite concentrates on board.py, which is pure and deterministic.

Drift worth naming: the ADR says advisor.py is "the only module that imports anthropic." In the shipped code no module imports it except __main__.py, lazily, once a credential is found — so the no-credential game does not even require the SDK to be installed. The code went further than the decision; the ADR text is stale on that line.

Full ADR-0002 text

The game is a single flat package, twenty48, split into five small modules ordered by how far each sits from pure logic:

  • board.py — the Move enum and the immutable Board value object. Pure, no I/O, no randomness of its own (RNG is injected). Holds the tested heart.
  • advisor.py — the Advisor protocol and its one ClaudeAdvisor implementation. The only module that imports anthropic.
  • ui.py — terminal rendering and key input, nothing else.
  • loop.py — the turn cycle, wiring board + ui + advisor together.
  • __main__.py — the composition root: the only place that reads environment variables, detects the credential, and builds the advisor.

Nothing above the advisor line knows Claude exists; nothing but __main__ touches the environment.

Considered options
  • src/ layout — rejected: marginally more correct for packaging, but adds ceremony out of proportion to a small terminal game.
  • advisor/ as a package — deferred: it stays a single module until a second advisor implementation actually exists (see ADR-0001). No speculative directory.
Consequences
  • The package is named twenty48, not 2048 — a module name cannot start with a digit (import 2048 is a syntax error).
  • Secret/credential handling is confined to __main__.py, so there is exactly one place to audit for "does this leak a key?"
  • The test suite concentrates on board.py, which is pure and deterministic.

The seam

Seven ways a hint can fail, one place it can land

The H key runs one synchronous call across a dashed seam. Every failure mode — missing credential, dead network, expired token, rate limit, refusal, malformed reply, or a move that isn't legal here — converges on a short status-line string. The game loop contains no try at all, because the Advisor is defined never to raise into it.

Six distinct messages exist, so the player learns something useful: re-authenticate, retry shortly, or the model just picked an illegal move. Play continues in every case.

ADR-0001

The Advisor is an optional, Claude-only seam

Chose one interface with a single Claude-backed implementation, optional at runtime and forbidden from throwing into the game loop, over keeping a local heuristic fallback or making the AI mandatory.

Rejected

  • ✕ Keep the prototype's heuristic as a local fallback — a second recommender to maintain for no current requirement. The seam is kept so it can return without touching the game core.
  • ✕ Make the AI mandatory — the repo must run with zero setup for anyone who clones it, and the brief forbids submitting credentials.

Consequences

  • →The seam has exactly one implementation today. Deliberate: an extension point, not speculative generality.
  • →Two credentials are accepted — ANTHROPIC_API_KEY as x-api-key, or CLAUDE_CODE_OAUTH_TOKEN as Authorization: Bearer plus an OAuth beta header. The API key wins when both are set, so two auth headers are never sent at once.
  • →The OAuth path was verified empirically against POST /v1/messages — a live 200 — and the three caveats it surfaced are all absorbed by the never-throws policy.

Named, not resolved: using a Claude Code subscription OAuth token for general Messages API traffic is a grey area — no primary source was found permitting or forbidding it. It stays a developer convenience; ANTHROPIC_API_KEY is the first-class path. Its tokens are also short-lived and subject to subscription rate limits, which is why 401 and 429 have their own status-line messages.

Full ADR-0001 text

The move recommender ("Advisor") is a single interface with one implementation, Claude-backed; the prototype's local heuristic is dropped. The Advisor is optional — the game is fully playable without it — and it never throws into the game loop: every failure (missing credential, network error, refusal, or a suggestion that isn't a legal move) becomes a short status-line message and play continues. The game core depends only on the Advisor contract, never on the anthropic package.

Considered options
  • Keep the heuristic as a local fallback — rejected: the user wants Claude only for now and doesn't want to maintain a second recommender. The seam is kept so a fallback can be re-added later without touching the game core.
  • Make the AI mandatory (refuse to start without a credential) — rejected: the repo must run with zero setup for anyone who clones it (graders included), and the brief says "do not submit with any credentials."
Consequences
  • The seam has exactly one implementation today. That is deliberate — an extension point, not speculative generality.
  • Authentication accepts either ANTHROPIC_API_KEY (sent as x-api-key; read automatically by the SDK) or CLAUDE_CODE_OAUTH_TOKEN (an OAuth token, sent as Authorization: Bearer plus the anthropic-beta: oauth-2025-04-20 header). ANTHROPIC_API_KEY takes precedence when both are set. The ClaudeAdvisor branches its client construction on which is present.
  • The OAuth-token path against the Messages API is verified working (issue #4; research note 0004): an sk-ant-oat… token sent as Authorization: Bearer returns a live 200 from POST /v1/messages. The verification surfaced three caveats, all absorbed by the "never throws into the game loop" policy above:
    • Subscription-tier limits. A CLAUDE_CODE_OAUTH_TOKEN is a Claude subscription credential, governed by subscription rate limits rather than per-org API tiers. In testing claude-haiku-4-5 succeeded but claude-opus-4-8 returned 429. The Advisor must not hardcode a model the OAuth tier may rate-limit; a 429 degrades to a status-line message.
    • Short-lived tokens. OAuth access tokens expire within hours and the Advisor cannot refresh them. A stale token returns 401, which degrades to a status-line message rather than a crash. A static CLAUDE_CODE_OAUTH_TOKEN env var can therefore go stale between sessions.
    • Terms of Service (unresolved). Using a Claude Code / subscription OAuth token for general Messages API traffic is a gray area; no primary source was found permitting or forbidding it. ANTHROPIC_API_KEY remains the clean, first-class credential, and OAuth is a convenience for developers already logged into Claude Code — not the path a grader is expected to use.
    • The anthropic-beta: oauth-2025-04-20 header was not strictly required against /v1/messages in testing, but the ClaudeAdvisor sends it anyway: harmless where unneeded, and future-proof against endpoint changes.

ADR-0003

Ask with structured outputs, then verify the answer locally

Chose the spec's own null-using JSON matrix under a short rules-and-goal system prompt, with the reply constrained to a fixed schema — { move: enum[LEFT, RIGHT, UP, DOWN], rationale: string } — and the returned move then checked against board.legal_moves(), over a per-turn dynamic enum, tool use, or parsing prose.

Rejected

  • ✕ Dynamic enum of only the legal moves — changes the schema every turn, losing schema caching, and local validation already guarantees we never act on an illegal suggestion.
  • ✕Tool use with a strict enum param — heavier machinery than a one-shot ask needs.
  • ✕Plain text, parsed by us — fragile.

Consequences

  • →The fixed schema caches across turns.
  • →Move legality is guaranteed by our pure core, not by trusting the model. The advisor's correctness never depends on the model behaving.
  • →claude-haiku-4-5 with extended thinking off — chosen for interactive response over maximal hint quality. Model and thinking live in one named constant, so sharpening hints later is a one-line change.
  • →Rationale brevity is enforced by the prompt, not the schema: structured outputs cannot cap string length.
Full ADR-0003 text

The ClaudeAdvisor sends the current board to the Messages API as the spec's exact null-using JSON matrix, with a short system prompt stating the 2048 rules and the goal (avoid game-over, maximise the chance of reaching 2048). The reply is constrained with structured outputs to a fixed schema:

{ move: enum[LEFT, RIGHT, UP, DOWN], rationale: string }

The returned move is then validated against the board's actually-legal moves. An illegal or no-op suggestion becomes a status-line message, never a crash — the advisor's correctness never depends on the model behaving.

  • Model: claude-haiku-4-5, extended thinking off — chosen for interactive responsiveness over maximal hint quality (the H key should return in ~a second, not stall the game). The model id and thinking setting live in a single named constant in advisor.py; sharpening hints later (Opus, or thinking on) is a one-line change.
  • Rationale length is enforced by the prompt, not the schema — structured outputs do not support maxLength on strings.
Considered options
  • Dynamic enum of only the legal moves — rejected: it changes the schema every turn (losing schema caching), and local legal-move validation already guarantees we never act on an illegal suggestion.
  • Tool use with a strict enum param — rejected: heavier machinery than a one-shot ask needs.
  • Plain text, parsed by us — rejected: fragile.
Consequences
  • The fixed schema caches across turns.
  • Move legality is guaranteed by our pure core, not by trusting the model.
  • Swapping model or turning thinking on is a single-line change.

Tests

Four seams, four hand-written fakes, no network

Same ladder, greyed out, with the test doubles pinned where they substitute. The seams were not added for the tests — they exist because effects belong at the edges — but every one of them turns out to be the place a test plugs in. No mocking library, no patching, no network, no sleeping: 61 tests in 0.12 seconds.

substitution points ↑
__main__.py Credential precedence is factored out into the pure select_credential(env), so it is testable with a plain dict — the wiring around it is verified by playing the game.
dict as env 6 tests
loop.py The highest seam: every effect is a keyword argument, so one call to run drives whole-game behaviour deterministically and returns the final Board to assert on.
ScriptedKeys → KeySource StringIO → Writer ScriptedRng → Rng FakeAdvisor → Advisor 11 tests
ui.py render writes to an injected writer and parse_key is a pure function, so both are tested as values — no terminal required.
StringIO → Writer 9 tests
advisor.py A fake client pins the exact request built — model, thinking, board-as-matrix, schema — and drives all seven degradation paths by raising canned errors.
FakeClient → Client 15 tests
board.py Pure and frozen, so the tests are input-to-output comparisons. The injected RNG is the only non-determinism, and a scripted one removes it.
ScriptedRng → Rng 20 tests

The rules came from a written brief with worked examples. Those examples are the fixtures — each after-board copied verbatim out of 2048.md, so a regression in the slide-and-merge rule fails against the spec's own numbers rather than against my reading of them.

Gaps

What I know is missing

the one I'd fix first

Nothing in the suite talks to the real Messages API

FakeClient stands in everywhere, so the tests pin the request shape — model, thinking, board matrix, schema — but prove nothing about the live contract. The OAuth path was verified by hand, once, and written up as a research note; that is a dated observation, not a regression test. If the API's structured-output field were renamed tomorrow, the suite would stay green.

Why it was acceptable here: the blast radius is bounded by design — a broken contract raises inside messages.create, hits the one except, and becomes "Advisor unavailable" while the game plays on. What I'd add: a nightly smoke test, marked and excluded from task check, before anything depended on this.

coverage

__main__.py at 65 %

The uncovered 15 statements are the SDK client construction and main() itself. The decision worth testing — credential precedence — was deliberately extracted into the pure select_credential and is covered. What's left is wiring I verified by playing.

coverage

ui.py at 80 %

The 11 uncovered statements are all in TerminalKeySource, the raw-mode termios reader. Isolating the untestable part into one 13-line adapter was the point; not testing it is still a gap, and it is where a terminal-handling bug would hide.

measurement

Line coverage only — no branch coverage

coverage.xml reports branch-rate 0: branch measurement was never switched on. It is a one-flag change (--cov-branch) that I simply didn't make, and until it is on, 90 % is a weaker claim than it looks.

design

One implementation, so the seam is unproven

ADR-0001 argues the Advisor is an extension point rather than speculative generality — but with a single implementation, that argument is untested. The honest check is the cheap one: a heuristic advisor would need no change to board, ui, or loop, only a second class satisfying suggest(board) -> Advice and one line in the composition root.

Deliberately out of scope, not overlooked: Windows support (input uses termios, so Linux and macOS only), score, persistence, undo, and continuing play past 2048. None appear in 2048.md; the brief's requirements are the boundary, and the win and lose conditions it does specify are both implemented and covered by golden fixtures.

And it's enforced, not just intended
